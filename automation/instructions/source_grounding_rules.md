# Source-grounding rules

1. Treat the supplied PDF as the authoritative source.
2. Preserve filenames, commands, interface labels, and terminology exactly as supplied.
3. Do not invent YAML schemas, command flags, UI fields, output fields, permissions, or error behavior.
4. Separate source-supported facts from missing execution details.
5. Convert missing implementation details into SME questions.
6. Select the document type that the evidence supports. Do not force incomplete source material into a detailed procedure.
7. Use the human-authored reference outputs as quality examples, not as additional product facts.
8. Require human review before publication.
